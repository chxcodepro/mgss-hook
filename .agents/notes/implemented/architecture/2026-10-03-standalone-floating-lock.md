# Agent Note: 手机端悬浮窗与动态币值锁

Status: implemented

## Problem

已有电脑 Frida 控制器能锁定本机资源，但关闭控制器会卸载脚本，无法由手机独立启动、切换和解除锁定。

## Decision

Android APK 同时提供悬浮窗前台服务和 LSPosed 模块，作用域限于微信 appbrand 进程。模块拦截已验证的 `h.k0` 入口，从当前请求的 `V8ScriptWxaFileDescriptor.wxaPkgPath/wxaFileName` 读取当前设备上的 WXA 源码，不打包固定版本游戏源码。五个币值特征及闭包末尾必须唯一匹配；失败保留原始请求。

微信 Tinker 使用 `DelegateLastClassLoader` 加载热更新类，因此钩子必须从 `Application.attach` 返回后的实际 Context 取得 ClassLoader，不能使用初始 `LoadPackageParam.classLoader` 的同名基础包类。基础包类可成功挂钩却完全接不到游戏请求，这会表现为模块有心跳、面板一直等待游戏。

闭包内注入控制器包装原始资源方法。金币、闪电分别受本机玩家 ID 与独立开关约束，蜜獾币包装原 getter/setter 和增减方法，未启用的逻辑继续调用原实现。开关关闭后资源从当前值继续正常变化，不回滚已发生的消费或持久化。游戏源码不修改到磁盘。

手机面板通过限本应用和微信 UID 的 ContentProvider 写配置；微信只能读配置、报告状态。模块通过 JSRuntime `evaluateJavascript` 更新状态，回调报告实际应用的修订号与数值。轮询作为通知丢失和后台进程恢复的后备。配置读取失败时停用全部锁定。悬浮窗关闭时撤销运行状态，收起时锁定继续。只有窗口自身处理触摸，窗口不获取键盘焦点。

初次安装需启用 LSPosed 微信作用域并重新启动微信，使模块能在 bundle 加载前安装。后续仅在手机点击运行，前台服务负责悬浮窗生命周期；运行时不需要电脑、USB、Frida 服务或脚本。点击运行后结束本应用 Activity 并返回原界面，不调用微信 Launcher，避免把已有小游戏切回微信聊天页。

## Alternatives considered

保留 Frida 并 eternalize 脚本可以复用注入链路，但手机仍需本地 Frida 启动器且脚本卸载、进程重启与文件桥接增加生命周期复杂度。设备已有 LSPosed，因此使用常驻 Java 模块。

打包当前解包源码可简化读取，但小游戏升级后可能执行旧版本完整 bundle。直接读取实际请求中的 WXA 文件可保证修改同一次请求的源码。

固定数值源码替换有已有验证，但不能即时切换单项或恢复原逻辑。控制器包装原方法保留关闭状态下的业务流程。

## Consequences

首次启用模块有一次设置成本，微信或小游戏结构变化时停止改写而非猜测地址。启动只显示三个锁定开关，不自动重启或终止正在运行的游戏。后台服务被系统终止时配置桥按失效状态撤销锁定，服务恢复后重新同步。

`tests/test_mobile_controller.mjs` 以设备当前包中的原方法验证全部八种开关组合、本机与人机隔离、关闭后恢复消费、蜜獾币标签刷新及心跳不重复持久化。`tests/BundlePatcherTest.java` 验证当前 WXA 读取、原源码保留及特征/闭包失败保护。旧固定值补丁测试也通过。

2026-10-03 实机安装 1.0.1 后，使用实际 Tinker 加载器命中两次目标 bundle。断开电脑 Frida 转发后，悬浮窗显示「已连接 3/3」，主界面蜜獾币和局内金币/闪电均为 999999；收起面板后可移动角色、选择建筑。关闭金币开关后状态变为 2/3，局内金币随生产增长到 1000001，闪电仍为 999999；重新锁金币并关闭闪电后，金币回到 999999，闪电随发电机产出增长到 1000000。验证后恢复全部锁定。
