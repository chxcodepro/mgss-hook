# Agent Note: 本人猎梦者等级控制与手机面板

Status: implemented

## Problem

用户选定手动升/降一级及输入目标等级。操作必须仅作用本人玩鬼的角色，并同步实际攻防数据。共享全局 `TrollUp` 事件可能升级其他鬼；只赋值 `level` 仅改标题，不能更新血量和攻击力。

## Decision

增加独立 `ghost.js` 控制器，在游戏原闭包内获取实际模式、主鬼管理器、输入角色 getter 和血量类。与[本人锁血](2026-10-08-self-ghost-health-lock.md)共用严格角色判定；求生、伥鬼及联机模式返回不可操作。

升一级调用当前受控角色的原 `xxl()`，指定较高等级逐级调用原升级流程。降级依据同版本等级表设置基础攻击、血量上限、升级间隔及等级标题，按原健康比例调整当前生命值，锁血开启时保持满血。一级使用初始化表项，二级及以上使用原升级的索引。已获得装备与技能保留，不回滚背包。上限取原规则 13 与当前三张表的实际可访问边界的最小值。

手机 Provider 使用单条带 UUID、角色/精灵 token 的命令与游戏回执通信。处理过的 UUID 不重复执行；旧局 token、非玩鬼身份和服务停止拒绝操作。等待回执时禁用等级按钮，超时撤销。等级操作不是持续等级锁，后续自然升级继续正常。

面板分“资源”“猎梦者”页签，保持原窗口宽度与拖动/收起操作；猎梦者页显示自身锁血、当前生命值、等级加减与数字输入。默认不开锁血。新增功能使用独立源码特征校验，失败只停用猎梦者控制，资源与广告保持可用。

历史笔记审计：本人锁血提案部分重叠，保持其隔离证据与双向关联；已有资源控制与广告相关笔记保留，不重写其决定。

## Alternatives considered

全局 `TrollUp` 事件能完整触发升级，但可能由多个鬼的逻辑监听，不满足本人范围。

直接赋 `level` 改 UI 成本低，但生命值、攻击力与经验节奏停留在旧档位。

持久化锁定等级能阻止自然升级，但用户明确选择手动控制；命令只执行一次。

## Verification

`tests/test_self_ghost_controls.mjs` 使用当前游戏包中的原血量及升级方法，通过升/降一级、目标等级、动态上限、非法输入、重复命令、命令超时、跨局 token 失效及非猎梦者模式隔离。原币值与广告测试通过，WXA 特征测试确认新功能不兼容时保留原控制器。

用户允许立即切换新版；1.1.0 已构建安装并重新进入小游戏。用户随后接手实机测试，发现原生白色数字弹窗上的文字为白色。1.1.1 改为黑色输入文字并构建安装，未继续代替用户操作手机。用户于 2026-10-08 明确反馈各项功能测试正常并授权推送、通过 Actions 发布；之前的临时锁血测试不冒充新版完整验收测量。

## Consequences

降级保留装备和技能，基础属性变更不等同于回滚曾获得的道具。微信热更新和游戏特征变化需明确停用新增功能。

命令最多等待五秒，带当前角色与精灵 token 和 UUID。重复心跳不会重复升级；超时在途命令不能晚执行。数字输入绑定打开弹窗时的角色 token，换局后确认会被拒绝。
