# Agent Note: 只为本人操控的猎梦者锁血

Status: implemented

## Problem

用户要求玩鬼时只对本人锁血。相同鬼对象在求生模式中由 AI 控制，因此只检查鬼类型、只找主鬼对象或对全部鬼阻断伤害都会在求生模式中让敌鬼无法被击败。分析、隔离及临时实机验证完成后，功能已集成 Android 面板。

## Decision

复用[手机端配置桥及闭包控制器](../../implemented/architecture/2026-10-03-standalone-floating-lock.md)，增加独立 `selfGhostHp` 开关，默认关闭。生效同时要求服务运行、开关开启、`T.mode === B.Troll`、战斗阶段有效、目标对象就是 `_.instance.xax`，且与游戏输入控制器 `nn.player` 的实际对象一致。角色精灵还必须匹配 `_.instance.troll`，有父节点、可见、未销毁；当前生命值及上限须为有效正数。

模式为求生、伥鬼、双人联机，或者角色身份/阶段不明确时，必须执行原始血量逻辑。开关配置可以保持开启，但生效状态必须立即变为未生效。每次判断重新读取当前控制对象，不能缓存上一局的鬼。

当前版本候选入口是 `yi.prototype.ljq` setter。锁定只替换目标对象此次写入的值为其动态上限 `hfv`，继续调用原 setter 完成数值取整、上限约束及血条更新。原 getter 保留，其他对象使用原输入值。开启时可以通过同一 setter 将存活目标补满；已死亡、退场或失去身份的对象不得复活。

该规则只针对 `B.Troll` 的猎梦者模式。被击败后转为伥鬼、其他联机鬼阵营不能直接沿用本判定，需要独立验证玩家归属后才能扩展。

`tools/analyze_self_ghost.mjs` 使用当前包里的原 getter、setter、hit、输入角色 getter 和管理器 getter，在隔离对象上验证候选条件。32 种模式/开关/服务/对象组合通过；致死伤害、动态血量上限、关掉开关、精灵退场/隐藏/销毁、死亡、异常上限、未开战及换局等边界通过。求生模式中即使接收对象就是主鬼，依然扣除原始伤害；猎梦者模式中的其他同类鬼也正常受伤。

最初分析只读取准备页；用户随后授权在其当前对局测试。临时实例钩子已通过本人身份、实际伤害入口、撤销后正常扣血、换局旧钩子失效及 519 次自然扣血检查，上限随等级从 400 增至 7680，实际血量保持满血。细节与验证边界见[实机记录](../../../../docs/testing/self-ghost-health-live-test-2026-10-08.md)。现已与[本人等级控制](2026-10-08-self-ghost-level-controls.md)一起集成面板。用户于 2026-10-08 完成 1.1.1 实机验收并反馈各项功能正常；未额外提供逐项测试数值，不将隔离测试冒充实机测量。

## Alternatives considered

在每秒配置心跳中给主鬼补满血实现简单，但一击致死会在下一次心跳前进入死亡流程，不能作为主要防扣血机制。

按鬼类型全局忽略 `hit()` 能覆盖大量伤害，但会同时保护 AI 鬼、额外鬼和求生模式中的敌人，违反只作用本人要求。

只判断 `this === _.instance.xax` 能准确找到主鬼对象，但求生模式中的主鬼也使用同一管理器，缺少模式条件仍会锁住敌鬼。

只替换 `hp` getter 为 1 可以让血条看似满血，但不能保证真实生命值与伤害、死亡流程一致。

## Verification

实际控制器测试覆盖本人及其他对象、求生/伥鬼/联机模式、致死伤害、上限变化、关闭开关、停止服务及不复活死亡角色。版本特征失败只停用猎梦者扩展，保留资源与广告，对应 Java 测试通过。APK 已构建安装，用户完成新版实机验收。

## Consequences

压缩类名和方法名会随版本变化；必须校验控制链及 setter，不能猜测新名称。对象身份不确定时关闭能力。

护盾、分身、特殊剧情或伥鬼机制可能另有生命值入口；本分析不声称覆盖这些对象和模式。实装必须避免把未知对象升级为默认保护目标。

锁血会影响低血量触发型技能，因为实际生命值保持满血；保留其他减伤、护盾及原始显示流程，具体低血技能行为仍需实机确认。
